# 服务化接口说明（app/）

> 本文件由「甲 · 后端与推理服务」补充，对应四人分工文档中的后端职责。
> 不修改原有 README 与算法代码，仅新增服务层。

## 1. 这是什么

把已经训练好的模型（BPR 召回 + LightGBM 排序）封装成 HTTP 接口，
让前端（乙）和教师测试集（丙）都能直接调用，不必关心模型细节。

算法部分完全复用 `src/` 与 `scripts/` 的现有实现，**没有改动任何原有代码**。

## 2. 启动方式

```bash
# 安装依赖（在原 requirements.txt 基础上补了 fastapi / uvicorn）
pip install -r requirements.txt

# 启动服务
uvicorn app.main:app --host 127.0.0.1 --port 8001
```

启动后：

| 地址 | 内容 |
|---|---|
| http://127.0.0.1:8001/ | 自动跳转到接口文档 |
| http://127.0.0.1:8001/docs | Swagger 交互式文档（可直接点按钮测试） |
| http://127.0.0.1:8001/redoc | ReDoc 只读文档 |

### 启动耗时说明

服务启动时会把模型和数据一次性载入内存：

| 场景 | 耗时 | 原因 |
|---|---|---|
| 首次启动 | ~37 秒 | 需要重新计算条目统计特征（`item_trend` 需遍历 8.4 万部电影）并训练 LightGBM |
| 二次及以后 | **~2 秒** | 特征与 LightGBM 都已缓存到磁盘 |

缓存位置：
- 条目统计 → `data/processed/item_stats_cache.npz`
- LightGBM 模型 → `C:\temp\movie_recsys_cache\ranker_cache.txt`

> 注：LightGBM 的 C 库不支持非 ASCII 路径，所以模型缓存放在 `C:\temp\` 而不是项目目录。
> 删除缓存文件即可强制重新计算。

## 3. 接口清单

| 接口 | 方法 | 用途 |
|---|---|---|
| `/` | GET | 重定向到 `/docs` |
| `/health` | GET | 健康检查、已加载模型、加载耗时 |
| `/predict` | POST | 单用户 Top-K 推荐 |
| `/predict/batch` | POST | 批量推荐（JSON 返回） |
| `/predict/batch/csv` | POST | 批量推荐（CSV 流式返回，适合教师测试集） |
| `/evaluate` | POST | 对预测结果 CSV 计算 NDCG@10 / Recall@10 / MRR@10 |
| `/movies/{movieId}` | GET | 查询电影名称与类型 |
| `/sample/users` | GET | 随机返回有效用户 ID（供前端测试） |

## 4. 请求与响应示例

### 4.1 单用户推荐

```bash
curl -X POST http://127.0.0.1:8001/predict \
  -H "Content-Type: application/json" \
  -d '{"userId": 42, "topK": 5}'
```

```json

    {"rank": 2, "movieId": 1396, "score": 0.091882},
    {"rank": 3, "movieId": 3062, "score": 0.091882},

    {"rank": 5, "movieId": 5388, "score": 0.084043}

  "latencyMs": 47.28

```

### 4.2 批量推荐（CSV，推荐给教师测试集使用）

```bash
curl -X POST http://127.0.0.1:8001/predict/batch/csv \
  -H "Content-Type: application/json" \
  -d '{"userIds": [42, 100, 999], "topK": 10}'
```


**输出格式与 `scripts/evaluate.py` 的约定完全一致**（`userId,rank,movieId,score`），

### 4.3 在线评估

```bash

  -H "Content-Type: application/json" \
```

## 6. 实现要点

### 6.1 模型加载策略

- **BPR 权重**：直接加载 `models/bpr_mf.pt`（`src/ranking/bpr.py` 训练产物）
- **LightGBM**：原 `train_ranker.py` 不保存模型文件，因此服务启动时按相同参数重新训练一次，
  训练完把 `booster` 缓存到 `C:\temp\`，后续启动直接加载

这样无需修改原有训练脚本，同时避免每次启动都重新训练。

### 6.2 特征构造

9 维特征与 `scripts/build_features.py` 保持一致：

`pop_log`、`item_mean`、`item_bayes`、`item_recency`、`item_trend`、
`user_activity`、`user_last_activity`、`genre_affinity`、`bpr`

条目统计特征在启动时从 `data/processed/train.npz` 重算，算完缓存。
`genre_affinity` 用 `movies.csv` 的类型向量与用户历史类型偏好做余弦相似度。

### 6.3 与原有代码的关系

| 复用 | 说明 |
|---|---|
| `models/bpr_mf.pt` | BPR 权重，直接加载 |
| `data/processed/*.npz` | 候选集、词表、训练集 |
| `data/features/valid.npz` | LightGBM 训练特征 |
| `movies.csv` | 电影名与类型 |
| `results/` 指标文件 | 评估对比基准 |

**未修改** `src/`、`scripts/`、`configs/` 下的任何文件。

## 7. 已知限制

1. **缓存路径含 `C:\temp\`**：因为 LightGBM C 库不支持非 ASCII 路径，
   这是当前项目路径含中文时的必要妥协。
2. **单用户延迟约 24–47 ms**：主要耗在 `genre_affinity` 计算（需扫描训练集找该用户历史）。
   如需进一步优化，可在启动时预计算所有用户的类型偏好向量。
3. **首次启动 37 秒**：主要耗在 `item_trend` 计算。若教师环境要求快速冷启动，
   可把 `data/processed/item_stats_cache.npz` 一起交付（约 2 MB）。
4. **并发能力未压测**：uvicorn 单进程模式适合演示，高并发需加 `--workers`。
